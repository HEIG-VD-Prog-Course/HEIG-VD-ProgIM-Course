## Structure de l'évaluation

### Section 1 : Vrai ou Faux (12 points)

- **Questions :** 6 questions
- **Points par question :** 2 points
- **Difficulté :** 5 faciles, 1 moyenne

- **Sujets couverts :**

  - Conventions de nommage

## Grilles de correction détaillées

Chaque question inclut :

- **Objectif pédagogique** : Ce qui est évalué
- **Points détaillés** : Distribution précise des points
- **Réponse complète** : Solution attendue
- **Critères de correction** : Comment attribuer les points partiels

### Exemple de grille (Question 30 - 15 points) :

```text
- Signature de méthode correcte : 3 points
- Calcul et retour : 2 points
- Création Scanner : 1 point
- Lecture 3 notes : 4.5 points (1.5 chacune)
- Appel de méthode : 2.5 points
- Affichage moyenne : 1 point
- Condition réussite/échec : 2 points
```

## Conseils pour la correction

### Utilisation des grilles

Chaque question a une grille de correction détaillée dans les balises
`<details>`. Utilisez-les pour :

1. **Correction cohérente** : Tous les correcteurs utilisent les mêmes critères
2. **Points partiels** : Valoriser les réponses incomplètes mais correctes
3. **Feedback précis** : Expliquer aux étudiants ce qui manque

### Points partiels recommandés

- **Code avec erreur de syntaxe mineure** : -10% du total
- **Logique correcte mais code incomplet** : 50-80% des points
- **Bonne approche mais erreur de calcul** : 60-70% des points
- **Commentaires manquants** : -5% (bonnes pratiques)

### Cas particuliers

**Question avec plusieurs solutions acceptables :**

- Question 27 : Deux approches (condition if ou incrémentation +=2)
- Accorder les mêmes points si la logique est correcte

**Questions de lecture de code :**

- Accepter des formulations différentes si le sens est correct
- Se concentrer sur la compréhension, pas la formulation exacte

## Conversion de la note

**Formule :** Note finale = (Total obtenu / 140) × 60

**Exemples :**

- 140/140 = 60/60 (note maximale)
- 112/140 = 48/60 (80%)
- 84/140 = 36/60 (60%)
- 70/140 = 30/60 (50%)

## Adaptation pour la plateforme d'évaluation

### Questions adaptables directement

- Vrai/Faux : Configuration native de la plateforme
- Choix multiples : Configuration native
- Choix unique : Configuration native

### Questions nécessitant un aménagement

**Diagrammes UML (Questions 18-19) :**

- Intégrer l'image du diagramme dans la question
- Créer des sous-questions séparées (a, b, c, d)
- Utiliser des zones de texte pour les réponses courtes

**Lecture de code (Questions 20-22) :**

- Afficher le code dans un bloc formaté
- Questions à choix unique pour les réponses précises
- Zones de texte pour les explications

**Complétion et écriture de code (Questions 26-31) :**

- Utiliser l'éditeur de code de la plateforme
- Activer la coloration syntaxique Java
- Prévoir un espace suffisant (30-40 lignes)

## Recommandations finales

### Avant l'examen

1. **Tester la plateforme** : Vérifier que tous les types de questions
   fonctionnent
2. **Préparer les diagrammes** : Générer les images PlantUML
3. **Configurer les temps** : Adapter si nécessaire selon la plateforme
4. **Préparer la documentation** : Liste des méthodes Java autorisées

### Pendant l'examen

1. **Surveillance des questions de code** : Vérifier que les étudiants ne
   bloquent pas
2. **Questions de clarification** : Noter les questions fréquentes pour
   améliorer l'énoncé
3. **Gestion du temps** : Rappeler les temps recommandés par section

### Après l'examen

1. **Correction rapide des QCM** : Automatique via la plateforme
2. **Correction du code** : Utiliser les grilles détaillées
3. **Feedback** : Partager les solutions avec commentaires
4. **Statistiques** : Analyser les questions difficiles pour ajuster le cours
